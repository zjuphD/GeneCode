# Architecture Baseline

## Product Shape

```text
Tauri desktop shell
├── React + TypeScript application
├── OVE behind an EditorAdapter
├── Agent sidebar and structured result UI
├── Transactional IndexedDB project/workspace mirror (web + Tauri webview)
└── Python design-service sidecar
```

## Implementation Status

Every capability below is marked **Implemented** (shipped and tested) or
**Planned** (designed but not yet built). Treat any undocumented capability as
Planned; this table is the source of truth (A-DOC-001).

| Capability | Status | Notes |
|---|---|---|
| Local API bearer token + health nonce (A-API-001) | **Implemented** | 256-bit token generated by the Rust shell, injected via `GENE_CODE_API_TOKEN`, exposed to the webview via `get_agent_api_token`; health returns `nonce`/`apiVersion` for restart detection |
| Transactional project/workspace store | **Implemented (web)** | `durablePersistence.ts` mirrors schema-validated, delta-compacted project/workspace snapshots into IndexedDB transactions; localStorage remains the synchronous first-paint cache and fail-closed recovery path. A native SQLite plugin is still **Planned** for multi-profile desktop sync/large libraries. |
| Long-sequence analysis worker | **Implemented (web)** | `sequenceWorker.ts`/`sequenceWorkerClient.ts` move restriction summary + GC statistics off the React main thread at ≥50 kb, with deterministic main-thread fallback for tests/older webviews. |
| Canonical sequence document + adapter | **Implemented** | `src/editor` canonical schema, OVE adapter, GenBank/SnapGene round-trip, origin-spanning `segments` (A-BIO-004) |
| Python sidecar lifecycle | **Implemented** | `ensure_agent_service` starts/reuses the sidecar on 127.0.0.1:8000, kills the process tree on exit |
| Agent planning + deterministic tool orchestration | **Implemented** | LLM or rules plan, snapshot/`planSnapshotHash` validation, server-side cancel (A-AGT-003) |

## Ownership

### Desktop Shell

- application lifecycle
- native file dialogs
- local project paths
- sidecar startup and shutdown
- secure local API token
- packaging and updates

### React Application

- project navigation
- sequence editor integration
- Agent interface
- patch and diff review
- QC and artifact presentation

### Python Sidecar

- sequence parsing and export
- cloning, primer, mutation, sgRNA, and siRNA design
- restriction scanning
- Agent planning and deterministic tool orchestration
- optional remote database access

## Canonical Sequence Boundary

OVE data is an implementation detail. The application owns a canonical
sequence document with stable IDs, sequence, topology, features, primers,
metadata, content hash, and version ID.

The editor adapter is responsible for:

- canonical document to OVE data
- OVE edits to canonical operations
- coordinate conversion
- feature and primer normalization

## Agent Change Boundary

The Agent proposes a structured `SequencePatch` against a specific document
version and content hash. The desktop application validates and previews that
patch. Only an explicit user action creates a new version.
